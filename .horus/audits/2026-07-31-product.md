# Product audit — horus-harness, 2026-07-31

## 1. What this document is

An inward evidence pass: what the delivered product actually is, measured against
this project's own Vision. **It decides nothing.** Every suggestion is routed to the
step that owns the decision.

## 2. The product, in plain terms

Horus is a repo-local memory-and-rituals layer for coding-agent CLIs. It keeps a
project's state in committed `.horus/` files any agent can read, and wraps that with
a CLI (62 subcommands), a terminal cockpit, a read-only hosted dashboard, and
machine-local plumbing for accounts, usage and scheduled work.

**Pinned intent for this run: deepen own-use.** Audience is the single
owner-operator, so findings read as *build-vs-adopt per capability*, never market
saturation.

**Subject pinned via:** the facet table in `PRD.md` (8 facets). Reference surfaces
derived from this repo: `horus/*.py` entry points, `.claude/`+`.agents/` skills,
`CLAUDE.md`/`AGENTS.md`, `tests/`, CI workflows, and machine-local `~/.horus/`
state. Overlap sources (declared, reusable): **Claude Code CHANGELOG**, **OpenAI
Codex release notes**, and the `.horus/` file contract itself as consumed by
sibling projects (fabric-build, pbi-ecosystem, horus-agent).

**Structural finding this window.** The measurement layer was rebuilt (PRs
#467–#477): committed continuity fell 276,884 → ~71,000 chars, and size/entry/handoff
budgets replaced a line cap that was structurally blind. That is real work, but it is
**debt repayment, not forward capability** — a reader looking at "what shipped since
the last audit" will overstate product motion.

## 5. Per-unit detail

### Dashboard / cockpit — the drift worth acting on

**Definition of done:** *"Owner sees fleet state and launches/resumes any project from
web or phone, no terminal command."*

**What stands:** launching works across three hosts. **herdr is genuinely adopted** —
of 26 sessions since v0.0.78, **11 carry herdr refs (`wN:pM`) and 14 tmux**. A large
recent investment that is actually used, which is the clearest build-vs-adopt win in
the window.

**The defect:** `stop_session` sets `status="failed"` with
`termination_reason="stopped"`, and `reap_orphans` does the same. So **an owner
closing a session is recorded as a failure**. Measured over sessions since the stamp:

```
36  ('failed',  'stopped')     <- the owner closed these
16  ('exited',  'natural')
 6  ('stale',   None)
 2  ('running', None)
 1  ('failed',  'natural')     <- an actual failure
```

**36 of 38 `failed` rows are owner-initiated closes — 56% of all sessions in the
window.** The cockpit's own signal tells the owner most of their work failed. This is
"sees fleet state" delivering a false state, on the surface used daily.

### PO lifecycle — divergence has outrun convergence

**47 explore vs 27 converge**, and **26 of 74 cards Deferred** — over a third parked,
including the whole X5 branch under an undated hold. The Vision's breathing model says
exploration converges or is dropped; neither is happening at this ratio. `explore-converge-lifecycle`
remains the named open card and is itself Deferred, waiting on a per-card usage signal.

### Autonomous dispatch — complete machinery, zero live usage

Envelope files exist for three drill batches; **no systemd timer is armed**. The facet
DoD describes a loop that "runs approved cards end-to-end", and 0 cards are
autonomous-eligible — an honest zero, with two drill legs deliberately reserved. The
gap is eligible work, not capability.

### Continuity core — strong, with the window's premise shifting

64 sessions resumed from durable state. But **Claude Code 2.1.219 shipped Opus 5 with
1M context**, which weakens one premise behind continuity-as-context-economy: a 57KB
PRD is trivial against 1M. What does *not* weaken is continuity as **durable
cross-session, cross-vendor state** — which is the actual thesis. Worth stating
explicitly so future work optimises the right property.
